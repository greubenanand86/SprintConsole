# Architecture Decisions

Technical ADRs: stack choices, API design, data model, infrastructure, and integration decisions.

Write an entry for any structural decision that would be costly to reverse or that a new engineer would need to understand to work safely in this codebase.

## Entry template

```markdown
# ADR-{NNN} — {Title}

**Date**: {YYYY-MM-DD}
**Status**: Active / Superseded by ADR-{NNN}
**Deciders**: {Architect Agent / human lead}

## Decision

{What was decided.}

## Context

{What problem required a decision? What constraints applied?}

## Alternatives considered

- {Option A} — rejected because {reason}
- {Option B} — rejected because {reason}

## Consequences

{What this locks in, what it enables, what it prevents.}

## Revisit when

{Condition or event that would warrant re-evaluating this decision.}
```
