# Release Learnings

Post-release retrospectives and process improvements. One entry per release that produced a meaningful learning.

Not every release needs an entry — write one when something went unexpectedly well or poorly, a process broke down, or a practice should be adopted or dropped.

## Entry template

```markdown
# Release {v{x.y.z}} — Learnings

**Date**: {YYYY-MM-DD}
**Release type**: Feature / Bugfix / Hotfix

## What went well

- {Item}

## What went wrong

- {Item}

## Process gaps identified

- {Gap} → {Proposed fix}

## Changes to make before next release

- [ ] {Action item} — owner: {Agent or human}
```
